# Telegram Giveaway Platform

Платформа для организации и автоматизации розыгрышей в Telegram.

Проект объединяет пользовательского и административного Telegram-ботов, веб-панель управления, REST API, фоновые задачи и планировщик.

Приложение работает с PostgreSQL и Redis, использует Celery для фоновой обработки задач и разворачивается в контейнерах с использованием Docker или Podman.

---

## Возможности

- пользовательский Telegram-бот;
- административный Telegram-бот;
- веб-панель управления;

- управление заявками;
- управление розыгрышами;
- автоматический запуск и завершение розыгрышей;
- проверка условий участия;

- периодические задачи через Celery Beat;
- миграции базы данных;

## Быстрый запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/limbovvv/tg-bot-clothes.git
cd tg-bot-clothes
```

### 2. Создать локальную конфигурацию

```bash
cp .env.example .env
```

После этого необходимо заполнить переменные окружения в `.env`.

Пример:

```env
POSTGRES_DB=
POSTGRES_USER=
POSTGRES_PASSWORD=

BOT_TOKEN=
ADMIN_BOT_TOKEN=

SECRET_KEY=
```

Фактический состав переменных зависит от текущей версии проекта.

> Рабочий `.env`, токены, пароли и другие секреты не должны попадать в Git.

## Healthcheck

В контейнерной конфигурации используются проверки состояния сервисов.

Они позволяют:

- проверять реальную готовность компонентов;
- корректно запускать зависимые сервисы;

- отличать просто запущенный контейнер от работающего приложения.

Проверка состояния:

```bash

```

Проверка backend:

```bash

```

Если backend доступен через Nginx:

```bash
curl http://localhost:8080/health
```

Фактический адрес зависит от конфигурации проекта.

## Резервное копирование

В проекте предусмотрен скрипт резервного копирования PostgreSQL:

```bash
./deploy/backup.sh
```

Резервные копии рекомендуется хранить отдельно от основной базы данных.

Сам факт наличия backup не гарантирует возможность восстановления.

Поэтому процедуру восстановления необходимо периодически проверять на тестовой базе данных.

---

## Восстановление PostgreSQL

Конкретная команда зависит от формата резервной копии.

Для восстановления могут использоваться:

```bash
psql
```

или:

```bash
pg_restore
```

Перед эксплуатацией необходимо документировать и протестировать полный сценарий:

```text
backup
   ↓
хранение
   ↓
восстановление
   ↓
проверка данных
```

## Redis и Celery

Redis используется совместно с Celery для выполнения фоновых задач.

Упрощённая схема:

```text
FastAPI
   │
   ▼
Redis
   │
   ▼
Celery Worker
```

Приложение передаёт задачу в очередь.

Celery Worker получает её и выполняет отдельно от основного HTTP-запроса.

Это позволяет не блокировать backend при выполнении длительных операций.

---

## Celery Beat

- завершение событий;
- обслуживание данных;

## Безопасность

При развёртывании проекта необходимо соблюдать базовые требования безопасности.

### Секреты

Не хранить в Git:

- Telegram Bot Token;
- пароли PostgreSQL;
- приватные ключи;
- API-ключи;
- секреты приложения;
- рабочий `.env`.

### База данных

Доступ к PostgreSQL следует ограничивать:

- внутренней контейнерной сетью;
- firewall;
- сетевыми правилами;
- отдельными пользователями БД.

### Контейнеры

Рекомендуется:

- использовать актуальные базовые образы;
- минимизировать количество установленных пакетов;
- не запускать процессы от root без необходимости;
- обновлять зависимости;
- проверять контейнерные образы на известные уязвимости.

### Веб-приложение

При дальнейшем развитии проекта необходимо учитывать:

- аутентификацию;
- авторизацию;
- управление сессиями;
- XSS;
- CSRF;
- SQL Injection;
- IDOR;
- brute force;
- безопасную обработку пользовательских данных.
